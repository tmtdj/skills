# Work plan

A rewrite can only describe work that happened. When a high-weight skill scores low, or a line is full of `[ASK]` gaps, the fix is real work at the person's job. This file has task examples and the progress file template.

## How to pick tasks

1. Start with the skills that have weight 3 for the target role and score Unacceptable or Capable.
2. Then the `[ASK]` gaps the person couldn't answer because the work or the number doesn't exist yet.
3. Pick 3 to 5 tasks. Each must fit inside their current job, take weeks not months, and leave proof a stranger could check.
4. Each task says: what to do, how long, the proof it leaves, and the CV line it would fill.
5. Sizes and periods in a task are suggestions. They never go on the CV. The CV gets the real result the person reports.
6. Every task is about doing more, faster, or with better checks. Never about removing people or roles.

## Task examples (all made up, slots in brackets)

### Product manager
- Build a working prototype of [an idea on your roadmap] with an AI coding tool and put it in front of [N] users within [period]. Proof: the demo link and user notes. Fills: skill 6, "Got [N] ideas in front of users in [period], up from [before]".
- Write a [N]-case test set for [an AI feature your team ships] and track its pass rate weekly for [period]. Proof: the test set and the pass-rate log. Fills: skill 3, "pass rate from [before] to [after]".

### Engineer
- Pick one repeat task (for example [test writing or dependency updates]) and hand it to a coding agent with a written brief and a definition of done for [period]. Log changes shipped and how you checked each. Proof: the brief and the log. Fills: skill 2, "Shipped [N] changes a [period], up from [before]".
- Track the cost per run of [one AI job you run] for [period], then try one change to bring it down. Proof: the before and after numbers. Fills: skill 5.

### Designer
- Take [one live brief] from brief to a tested working prototype, and time it against your usual process. Proof: the prototype and [N] recorded user tests. Fills: skills 1 and 6.

### Data or analyst
- Set up an AI assistant for [one recurring question you answer], with [N] checked example answers it must match before you trust it. Proof: the example set and its match rate. Fills: skills 3 and 4.

### Marketer
- Build a draft-and-review workflow for [one content type], with a written checklist every piece passes before it goes out. Count tests run per [period] before and after. Proof: the checklist and the test log. Fills: skills 1 and 3.

### Ops, team lead or founder
- Move [one team workflow] to an agent-assisted version with a named checkpoint and reviewer role. Track the time it gives back and what the team spent it on, for [period]. Proof: the workflow doc and the time log. Fills: skill 9, "Moved [team] to [workflow]; [what the freed time went to]".
- Write a shared context file (product facts, tone, rules) that your team's AI tools start from, and note how many people use it after [period]. Proof: the file and its users. Fills: skill 4.

### Junior or career changer with no AI on the CV
- Pick one task from your current job or a course project and do it with an AI tool, then check the output against [a simple checklist you write]. Proof: the checklist and a short write-up or repo. Fills: skills 1 and 3 at Capable, then Adoptive once there's a before and after.

## Progress file template

Save as `cv-work-plan.md` in the working folder. Private. No phone, email or address.

```markdown
# CV work plan
Target role: [role, location]
Last run: [date]
Score on the page: [level] ([score]). With answers: [level] ([score]).

| # | Task | Skill | Started | Status | Result (with baseline and period) | Proof | CV line it fills |
|---|---|---|---|---|---|---|---|
| 1 | [task] | [skill] | [date] | open | | | [line with ASK slots] |
```

Status is open, going, done or dropped. On a follow-up run, fill Result and Proof only from what the person reports. Never delete rows.
