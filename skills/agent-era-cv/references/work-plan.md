# Work plan

Recommendations can only point to work that happened. When a high-weight skill scores low or is missing, or the person has no outcome to show yet, the fix is real work at their job. This file has task examples and the progress file template.

## How to pick tasks

1. Start with the skills that have weight 3 for the target role and score Unacceptable or Capable. Outcomes from AI is weight 3 for everyone, so a task that moves a real metric comes first.
2. Then the gaps the person couldn't answer because the work or the number doesn't exist yet.
3. Pick 3 to 5 tasks. Each must fit inside their current job, take weeks not months, and leave proof a stranger could check.
4. Each task says: what to do, how long, the outcome to measure, the proof it leaves, and the recommendation it would make true.
5. Sizes and periods in a task are suggestions. They never go on the CV. The CV gets the real result the person reports, in their own words.
6. Every task is about doing more, faster, or with better checks. Never about removing people or roles.

## Task examples (all made up, slots in brackets)

### Product manager
- Build a working prototype of [an idea on your roadmap] with an AI coding tool and put it in front of real users within [period]. Measure [outcome] before and after. Proof: the demo link and user notes. Makes true: skills 1 and 6.
- Write a [N]-case test set for [an AI feature your team ships] and track its pass rate weekly for [period]. Proof: the test set and the pass-rate log. Makes true: skill 5.

### Engineer
- Pick one repeat task (for example [test writing or dependency updates]) and hand it to a coding agent with a written brief and a definition of done for [period]. Log how you checked each change and the time to merge before and after. Proof: the brief and the log. Makes true: skills 3 and 4.
- Track the cost per run of [one AI job you run] for [period], then try one change to bring it down. Proof: the before and after numbers. Makes true: skill 8.

### Designer
- Take [one live brief] from brief to a tested working prototype, and time it against your usual process. Proof: the prototype and [N] recorded user tests. Makes true: skills 3 and 6.

### Data or analyst
- Set up an AI assistant for [one recurring question you answer], with [N] checked example answers it must match before you trust it. Proof: the example set and its match rate. Makes true: skills 5 and 9.

### Marketer
- Build a draft-and-review workflow for [one content type], with a written checklist every piece passes before it goes out. Measure [outcome] before and after. Proof: the checklist and the results. Makes true: skills 1 and 5.

### Manager, ops or founder
- Move [one team workflow] to an agent-assisted version with a named checkpoint and reviewer role. Track the cycle time before and after and the outcome it moved, for [period]. Proof: the workflow doc and the numbers. Makes true: skills 1 and 7.
- Write a shared context file (product facts, tone, rules) that your team's AI tools start from, and note how many people use it after [period]. Proof: the file and its users. Makes true: skill 9.

### Junior or career changer with no AI on the CV
- Pick one task from your current job or a course project and do it with an AI tool, then check the output against [a simple checklist you write]. Proof: the checklist and a short write-up or repo. Makes true: skills 3 and 5 at Capable, then Adoptive once there's a before and after.

## Progress file template

Save as `cv-work-plan.md` in the working folder. Private. No phone, email or address.

```markdown
# CV work plan
Target role: [role, location]
Last run: [date]
Score on the page: [level] ([score]). With answers: [level] ([score]).

| # | Task | Skill | Started | Status | Result (outcome, before and after, period) | Proof | Recommendation it makes true |
|---|---|---|---|---|---|---|---|
| 1 | [task] | [skill] | [date] | open | | | [where the line goes and what it shows] |
```

Status is open, going, done or dropped. On a follow-up run, fill Result and Proof only from what the person reports. Never delete rows. The person writes the CV line themselves.
